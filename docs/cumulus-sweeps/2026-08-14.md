# Cumulus Production-Liveness Audit — 2026-08-14

**Date:** 2026-08-14

**Audited range:** `ffbc62b778e66359ce955078ac065678d8dcd616`..`4028195f754e342388f5616bff1ae5d233574bae`

**Pre-sweep head:** `4028195f754e342388f5616bff1ae5d233574bae`

This sweep audited the complete current Cumulus catalog, not only files touched
in the range. A component, prop, nested field, variant, or behavior counts as
production-live only when all of these are true:

1. a deployed entry point can reach it;
2. normal canonical data or a valid player state can construct it;
3. the implementation reads it; and
4. the read affects rendered output, accessibility, state, or an interaction
   consumed by the product.

Imports, JSX callsites, populated view-model fields, docs, tests, `?goto=` QA
scenes, screenshot-frame injection, editor routes, and developer/operator
controls are evidence leads rather than liveness proof. Operator/debug behavior
is identified separately because some tools ship in the deployed bundle while
remaining outside normal gameplay.

## Dead-Code Disposition

The follow-up implementation rebased this audit onto `15b4ee38b4cc` and made
the verified zero-effect boundaries exact. Rich text is exposed through its
live model and `renderRichText` helper; the catalog contains player-renderable
components only. GlassPanel accessories are one labeled button or one icon
button, and subtitles are plain localized copy. Tutorial dialogue floating
placement describes only its placement kind because obstacle avoidance is
unconditional.

Transfiguration view models carry presentation, affordability, price, effect
details, preview, and workflow identity only at the layer that consumes each
field. The detail panel exposes its paintable `idle` and `submitting` states.
Exploration descriptions contain the two producer-backed part kinds, and the
Transfiguration picker contains the two builder-backed availability states.
OfferTile receives subtitle and background image number rather than the full
Augury presentation, and Atlas secondary reveal models contain only rendered
copy, art, and glyph data.

## Catalog And Reachability

The generated adoption number was not a component-consumer count. It counted
any value import of the component's source module, so sibling exports inherited
one another's importers. The generator now labels this honestly as
**Source-module importers**, explicitly states that it is not a liveness
measure, and excludes `__type_tests__` fixtures
([consumer index](../../scripts/lib/cumulus-consumers.mjs),
[docs generator](../../scripts/generate-cumulus-docs.mjs)). Disposition: metric
label and type-fixture exclusion fixed; symbol- and reachability-aware adoption
is part of the recommended program.

## Production-Unexercised Elements, Props, And Behaviors

These APIs are implemented, but valid normal-player production state does not
construct them:

- **Inputs and primitives:** `NumberStepper` and `TextArea` are wholly outside
  the player workflow. Player `TextField` is search-only; text/default kind,
  commit, support/error copy, disabled state, and omitted test id are absent.
  Player `Select` never uses full width, placeholder/unmatched selection,
  trigger labels, disabled options, omitted glyph/label/onChange, or an omitted
  leading glyph. `StandaloneGlyph.label` is never supplied, so its semantic
  role/label branch is dormant. `Pressable` has no ignored explicit prop, but a
  custom-component `as` and missing-provider/browser fallbacks are not deployed
  states.

- **Actions:** `IconButton.overlayGlyph`, `GlassButton.glyph`, and
  `GlassButton.pressed` are editor/operator-only. `TransfigurationButton`
  cannot receive `Perfected`; production offering excludes composite forms.
  `ExplorationChoice`'s `copies ?? 1` fallback is bypassed because builders
  always supply copies.
  `DisclosureSection` player usage always has summary, on-media placement, and
  test id. The on-glass/algorithm variants belong to tools.

- **Text and status:** RichText definition `symbolOnly` is absent from canonical
  data, and only `exhaust` is produced
  among the optional definition symbols. `RulesText.owner.kind="dreamsign"`
  is editor-only at the component boundary. Character dialogue never produces
  `dream-avatar-cutout` or `dream-guide` portraits. `TutorialFeatureCallout`
  never receives `testId`. Every production toast supplies `onDismiss`, so the
  non-dismissible branch is dormant. `JourneyStatusBar`'s empty-avatar
  placeholder is unreachable in a valid journey: Journey Start bypasses chrome
  and the transition to Dreamscape atomically assigns the avatar. Compact
  battle status is also absent because battle chrome mounts only on desktop.

- **Cards:** `PlayingCard.emphasis="current"` has no player constructor.
  `WagerPrizeCard.prizeId="blackjack"` is absent; Blackjack uses `PlayingCard`.
  `CardPile` figment cards are invalid under battle rules because Figments
  cease to exist when leaving play. Player `CardBrowserPanel` never uses
  `embedded` or mutation gestures;
  those are editor/operator behavior. Player pickers never use draggable cards,
  quantity badges, footer glyphs, or footer essence costs.
  `CardBack.testId` has no player caller. `CardStatOrb` accepts cross-products
  that production does not: energy+kindled, spark+empowered, any Dreamwell
  badge, and a custom label on ordinary stats. `CardChangePair.reveal="before"`
  occurs only for transfiguration and card-type changes. A detail candidate is
  always nonempty, and its controlled value is null or one of its forms.

- **Sites and overlays:** `DeveloperRail.testId` has no caller. `edgeRail` and
  explicit `GlassDialog.fullScreen` are developer-only. InfoCard's six variants
  are all genuinely player-live, but text subtitle, full-bleed figure,
  text-variant omission, full-bleed center crop, and atlas-reveal top crop have
  no producer. `SiteLayout.scene=null` is corrupt/imported-state defense rather
  than a valid site state.

- **OfferTile:** Four draft-like kinds are configured at exactly four choices,
  so their accepted two/three-card cardinalities are dormant.

- **Battle:** enemy perspective, reveal-all far hand, hide-near-hand,
  stored-memory values above zero, most `BattlefieldCard` selection variants,
  deck-order `top-N`, `CardOrderEditor` on-media placement, and
  `BattleResultSurface.centerOnBattlefield=true` are operator-only. The player
  BattlefieldCard selection set is playable/highlighted/selected. The battle
  log overlay always receives empty turn history, so its turn-history rows and
  seven history filters cannot populate; raw log entries can. Foresee itself is
  player-live, but initial count above one and noncontiguous allowed-count sets
  have no authored source.

Production-visible Main Menu actions also expose inert behavior. Dream Codex,
Settings, About, Quit, GitHub, Discord, and Reddit dispatch, but the fold returns
unchanged state; only New Journey changes state
([front-door.ts](../../src/rules/front-door.ts)). Disposition: filed in
`pre-existing-issues.txt`.

## Demo And Doctrine Drift

The catalog can display a demo while the dominant production integration or
valid state space remains untested. Verified high-value cases:

- GlassDialog and GlassPanel demo wrappers ignore generated args, producing
  visible but inert controls.
- AtlasNode labels a `revealedLocked` fixture as forgone; production has a
  distinct `forgone` state. Dreamsign omits live revelation/unavailable states.
- OfferTile demonstrates one of thirteen enabled kinds.
- InfoCard is mounted bare instead of through the Entity Reveal Coordinator.
  TutorialFeatureCallout is mounted without its measured card/leader
  integration. TidesInfoLabel is mounted outside its HUD group.
- CharacterDialogue drops its live playback-speed control. RadialAnnouncement
  hardcodes most state while controls imply interactivity. CoopPresence omits
  the live null/Connecting state. JourneyStatusBar's fixture is structurally
  invalid and omits overflow and deck activation.
- DreamsignReplacementDialog offers held/capacity combinations that cannot
  trigger replacement. CommandMenu combines app-chrome and battle-context
  commands that no product model combines.
- BattlefieldCard demos expose dead selection values and omit live
  highlighted/travel states. CardOrderEditor documents on-media while its only
  integration uses on-glass.

Doctrine comments also asserted stale universal contracts. This sweep corrected
the shared-breakpoint claim, universal Essence presentation, mote-only opacity
animation, JourneyStatusBar reveal inventory, universal DreamAvatar reveal,
stale tide-source consumers, the control-treatment consumer role, and the
`CardView` player-usage claim. The design-system lifecycle section's deleted
`CardTermDefinitions` reference was also removed. Disposition: source doctrine
fixed; demo repairs belong to the recommended program because many require
production-owned integration fixtures rather than copy edits.

- Dreamsign replacement is reachable from capacity overflow in Dreamscape,

## Recommended Program

### Production-aware component lifecycle

Replace the module-import adoption proxy with an inventory keyed by exported
symbol and production class. The generated reference should report at least:

1. player-production renderers;
2. deployed operator/debug renderers;
3. DEV/server-only renderers; and
4. docs/tests only.

The reachability layer should understand route/build gates and allow a small
reviewed manifest for canonical-state proofs that static imports cannot supply.
Use it to decide whether `EditableInfoCard`, `TextArea`, `NumberStepper`,
`DeveloperRail`, `CardOrderEditor`, and `GlossaryTerm` should be
deleted, reclassified as tools, or assigned a production adoption role. Add
`GalleryActionCard`, `CardView`, `GlassBackdrop`, and `PlayingCardSuitMark` to
the appropriate reference inventory.

### Boundary-shaped view models

Replace whole domain objects with presentation projections and discriminate
branch-specific props. Start with OfferTile/GameCard card snapshots,
AtlasNode/SiteNode domain objects, Transfiguration detail/button models,
JourneyStatusBar journey-vs-battle props, and the MobileBattle view. A field
should appear at a component boundary only when that component or a delegated
child reads it. Add type-level fixtures for invalid combinations such as
GlassDialog flowing subtitle, CardStatOrb badge/variant cross-products, and
card-change reveal states.

### Production-owned demos

Build fixtures through the same builders and integration owners used by the
product. Generated controls must either affect the specimen or be absent. The
first tranche should cover reveal coordination, OfferTile's full union,
Atlas/Dreamsign lifecycle states, tutorial measured guidance, battle-card
selection/motion, responsive JourneyStatusBar, nullable Coop presence, and
replacement-capacity invariants.
