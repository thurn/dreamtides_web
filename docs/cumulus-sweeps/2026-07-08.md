## Findings

- **GlassButton carried a stale incubating badge while it had a real consumer.**
  Evidence: `src/cumulus/docs/demos/glass-button.tsx:47` marked the component
  `status: "incubating"`; generated docs reported one real consumer, and
  `src/cumulus/screens/DreamsignRevelationScreen.tsx:440` renders it in
  production. Disposition: fixed in `9f63e06a`.

- **SiteNode mixed literal values with existing semantic tokens.** Evidence:
  `src/cumulus/components/dreamscape/site-node.css:39` and `:96` used `#fff`
  where `--text-on-accent` exists; `:95` used `#14101f`, the value behind
  `--bg-band` in `src/cumulus/primitives/cumulus-tokens.css:189`. Disposition:
  fixed in `9f63e06a`; `--bg-band` became a live token reader and left the
  orphan-token baseline.

- **ResourceChip prose overstated its routing role.** Evidence:
  `src/cumulus/docs/demos/resource-chip.tsx:13` claimed every economy number
  routes through ResourceChip, while current production has one ResourceChip
  consumer and many `EssenceValue` / `EssenceGlyph` consumers; `ResourceChip`
  reads the shared `ECONOMY_MARKS` table. Disposition: fixed in
  `9f63e06a`.

- **Doctrine comments and docs carried stale scale and animation claims.**
  Evidence: `docs/journey_prototype/cumulus_design_system.md:298`,
  `docs/journey_prototype/cumulus_design_system.md:379`,
  `docs/journey_prototype/cumulus_design_system.md:401` described `--press-scale`
  as `0.94`, while `src/cumulus/primitives/Pressable.tsx:50` and
  `src/cumulus/primitives/cumulus-tokens.css:466` define `0.9`;
  `src/cumulus/components/hud/Motes.tsx:3` and `:113` described Motes as the
  whole system's opacity-animation channel while several screens use opacity
  animation for transitions and pulses; `src/cumulus/primitives/cumulus-tokens.css:468`
  described every hover-revealing surface as reading `--hover-scale`, while map
  nodes read `--node-hover-scale`. Disposition: fixed in `9f63e06a`.

- **The implementation-plan roster had stale component facts.** Evidence:

## Recommended Program

The filed findings cluster around catalog adoption and integration-surface
honesty: one-consumer entries, bare demos for surfaces that production uses
through wrappers, and helper APIs that agents discover by grep. A follow-up
program should define the catalog policy for one-consumer components, add
integration demos for screen-level surfaces, and add primitive/helper references
for high-import APIs.
