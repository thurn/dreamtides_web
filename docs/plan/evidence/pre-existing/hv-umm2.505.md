# hv-umm2.505 pre-existing observations

- The loop tracker's history (`state.loops.actions`, `src/engine/loops/tracker.ts`) records each step's answers as submitted, so it can replay them verbatim. Two chooseCards or chooseTargets answers that `canonicalAnswer` treats as the same set still leave different full-state hashes through that record, though every loop checkpoint signature agrees. The order contract in `take-from-among-count.contracts.ts` therefore compares the state with that answer record set aside, plus the checkpoints. Canonicalizing recorded answers is outside this bead's areas.
- `discard` (`src/engine/effects/primitives/discard.ts`) discards a chosen count of cards in the submitted answer order, so set-equal answers give different void order, `enteredZoneAt` order and discard event order. `shuffleInto` (`shuffle-into.ts`) moves its chosen hand cards in submitted order as well. `lookAtTop` already takes its chosen cards in offered order. Both are outside this bead's areas.
