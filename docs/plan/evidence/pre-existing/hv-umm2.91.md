# Pre-existing issues found by hv-umm2.91

- **The content inventory reports "this character's ✦" as an existing primitive.** `docs/plan/evidence/content-inventory.json` lists `valueCardStats` as `exists: true` with `usedBy: 14` and the note "\"this character's ✦\", \"that card's cost\"", but its only form is `costOf` (`src/engine/dsl/builders.ts`); no value read a card's spark before this bead added `thisCharacterSpark()` (`src/engine/dsl/values.ts`). Beads routed to `valueCardStats` for a spark read will find the in-play form here. Smallest fix: have `scripts/content-inventory.ts` list `thisCharacterSpark` beside `costOf` as the forms of `valueCardStats`.
- **No last-known spark exists for a source that has left play.** Cards still pending read "this character's ✦" after their character leaves play: Cinderheart (8624f9c7-dc92-4f4a-9c79-319b9c121b19, "▸Dissolved: Gain ⍟ equal to this character's ✦"), Defiant Holdout (a7c2ee76, "▸Dissolved: Materialize X … where X is this character's ✦"), and Cloaked Sentinel (75bf1aab, "Abandon this character: Dissolve an enemy with ✦ less than or equal to this character's ✦"). MTG 608.2h and RD-hv-umm2.67-1 and RD-hv-umm2.108-1 read such values as the card last was, but `thisCharacterSpark()` reads 0 once its source has left play (RD-hv-umm2.91-2, Open). Smallest fix: record the source's effective spark as it leaves play on each queued trigger and stack ability it sources (`QueuedTrigger` in `src/engine/state/types.ts`, its saved-state validator `isQueuedTrigger` in `src/rules/battle/fold.ts`, and the env built by `src/engine/steps/kinds/resolve-trigger.ts`), and read it in `ValueScope.sourceSpark`.
