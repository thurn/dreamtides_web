# RD-hv-umm2.92-1: Paying with cards from a named public void

- Ladder: Existing normative rules decide this composition; no D10 fallback analogy is needed. § Costs, Requirements, and X, § Targeting, § Zones → Void and § Banish supply precommit cost choices, exclusions, public information and the owner destination. The new concise cost paragraph records that application.
- Affects: cfa78375-85b7-47e9-95f5-b31e6d112c52.
- Source: Current `docs/rules.md` sections above and `docs/plan/engine-design.md`'s play/activation pipeline. The printed clause explicitly names the opponent's void and pays 1●; it is not an unqualified all-void instruction.
- Outcome: `banishFromAnyVoidCost` is a fixed-count PaymentCost with an explicit relative void selector (`you`, `opponent`, `any`), defaulting to `you` like existing void references. Ruin Scavenger passes `opponent` explicitly. Matching physical cards are chosen as a cost rather than targeted; the played source, earlier payments and preselected targets are excluded. Energy/card costs commit together, cancellation pays nothing, and banishment uses each card's owner destination. Public void cards do not disclose private hand/deck identities.
- Composition: The card's activated ability pays 1● and one opponent-void card, then gives itself permanent +1✦ (base) or +2✦ (amplified) through existing `gainSpark`. No stated duration uses that primitive's existing permanent default. There is no extra interaction beyond primitive composition, so D20 requires no real-card scenario module.
- Replacement: Created cards cease when they would enter a void, so a legal void-cost candidate is not a created card persisting there. Synthetic contracts instead cover a created source that ceases while a different composed cost is paid, with the captured ability origin/controller retained.
- Scope: No X form or new effect operation is introduced. Existing own-void fixed/X payments retain their semantics and staging. New prompt purpose uses relative ownership ranking and the existing void-card gallery; no picker or screen body is changed.
