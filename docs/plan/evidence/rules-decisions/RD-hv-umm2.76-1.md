# RD-hv-umm2.76-1: A count of cards in a zone is read whenever it is checked, never counts a card on the stack, and filters only a void
- Ladder: 4 (MTG analog: CR 608.2b, a resolving spell checks its targets again, reading any number a restriction uses at that time, while the spell itself is on the stack and not in a graveyard; CR 401.3 and 402.3, the number of cards in a library or hand is available to every player while the cards are not), then 5 (simplest reading consistent with every affected text) for the hidden-zone filter; steps 1–3 are silent: no D-, C-, or P-entry counts zone cards, the prototype implements none of these cards, and the `~/dreamtides` Rust engine has no ✦ bound that reads a count
- rules.md: § Zones → Counting cards in a zone; § Targeting → Bounds that count
- Affects: 2a8dff0b-759f-40cc-af40-393a4e7129d4 ("✦ less than or equal to the number of cards in your void"); 017a7b4b-3ccf-4635-9956-28a72b22274e, 5639053e-1fe3-4a42-b9c3-3fdf894bfab6, 8896c178-757e-4775-b117-a4357ebfe30f, f46490a5-7030-4ade-93e9-bedb5813f590 ("+1✦ for each … in your void"); and every other entity the content inventory routes to valueZoneCounts
- Why: rules.md defined references to the cards in a zone but not a number counted from one. A count reads the zone when the number is read, with "your" read as for references (RD-hv-umm2.59-2). As a target restriction it is read as targets are offered and again as the chosen target is checked on resolution, so a response that empties the void, or raises the enemy's ✦ above the count, leaves Weight of Memory without a legal target, and one that grows the void keeps it legal. The event being played is on the stack, so it never counts itself; it reaches the void only after it resolves. A static "for each" reads the count live, through the characteristics of the layers before its own (engine-design § Continuous effects), so a void card's changed type is respected and no layer reads itself. A void is public, so its count may filter by type, subtype, and copiable cost. A hand's or deck's size is public but which of its cards match is not, and a filtered count would publish that through the effect's visible result; every affected text counts a void, so a hand or deck count is unfiltered, which the DSL enforces (`CardCountValue`, `countCards`). Because a count reads only public information, every view computes the same legal targets and results, and no view, event, or log names a counted card.
