# RD-hv-7x4l.7-1: A resolving effect's continuous changes fix their characters and values as it resolves; a static "have" stays live
- Ladder: 4 (MTG 608.2h: dynamic values in a resolving spell or ability are determined once, as it resolves; MTG 611.2c: a continuous effect from a resolving spell that changes characteristics affects only the objects it affected at resolution)
- rules.md: § Spark → Values fixed as an effect resolves
- Affects: 3cda9dd7-cb81-43c1-9db5-1444d7363e13 ("Until end of turn, characters you control have +X✦ where X is the number of characters you control") and every "+X✦ where X is …", "… until end of turn" anthem, base-spark, keyword, and type change made by an event or a triggered or activated ability
- Why: rules.md did not say whether "+X✦ where X is the number of characters you control" changes as the count changes, or whether a character that arrives later is covered. Fixing both at resolution matches MTG, keeps a resolved effect's meaning stable for the rest of its duration, and lets the engine store each change as plain data (one floating record per character, with the number already computed). Static abilities ("Warriors you control have +1✦", Support, "+2✦ for each character supporting it") describe a state rather than an event, so they are re-read whenever characteristics are computed. The DSL marks the intent with `lockedAtResolution(value)`; every value a resolving continuous primitive reads is evaluated once either way.
