# RD-hv-umm2.453-1: Each discard instruction or payment is one counted occasion
- Ladder: 4, adapted from the Magic Comprehensive Rules; current Dreamtides cost order and created-card privacy supply the local payment and replacement details.
- rules.md: § Zones → Discarding one or more cards; § Costs, Requirements, and X. Earlier anchors: RD-hv-umm2.116-1, RD-hv-7x4l.50-1, RD-hv-7x4l.50-2.
- Affects: c86c1364-6ac4-4c90-8053-4e49441a2c83.
- Source: [Official Magic Comprehensive Rules, effective September 25, 2026](https://media.wizards.com/2026/downloads/MagicCompRules%2020260925.txt), 603.2c, 700.1, 701.9, 608.2c.
- Why: The local per-card discard ruling establishes who discards and counts created replacement, but does not define an aggregate occasion. Current pending content supplies no implemented batch precedent; the read-only Rust engine exposes per-card Discarded triggers and its applicable text supplies no aggregate clause. Magic treats trigger wording as defining the observed event, follows written instructions in order, and defines discard as a hand action. Adapted here, each instruction, payment descriptor, whole-hand redraw instruction, and hand-limit choice completes one occasion, independently of other instructions in the same step. This payment grouping follows Dreamtides' existing ordered descriptors; it is not a claim about Magic payment sequencing. Zero discards trigger nothing. The matched positive actual count includes created cessation and Reclaim banishment, stays captured while the FIFO waits, and is public without any card IDs. Existing hidden subject and created-card visibility rules govern the individual announcements. The printed once-per-turn clause uses the source ability's existing limit, without a global first-discard counter.
