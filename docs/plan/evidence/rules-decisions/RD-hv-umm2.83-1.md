# RD-hv-umm2.83-1: Random zone references pick different matching cards at resolution, without shuffling the deck

- Ladder: 3 for the untargeted form; 4 (MTG Arena's Alchemy "seek", a random matching card from the library, which leaves the library unshuffled); the existing normative unshuffled-deck tracking rule settles position knowledge.
- rules.md: § Zones → References to cards in a zone; § Keywords and Effects → Put on top or on the bottom of a deck (unshuffled-deck tracking); § Keywords and Effects → Materialize.
- Affects: 4a8bdcd7-cf88-48d4-80d0-a83fd6617d81, 7b55efd1-6d9f-4156-9de7-1c71ccc410cb (base; neither has amplified text).

"Two random ≤2● cost characters from your deck" names that many different cards chosen uniformly among the matching cards of the zone, as the effect resolves. Nobody chooses them and they are not targets, so nothing is checked at play time and no `noLegalTarget` is reported. With fewer matching cards the reference names all of them, and with none it names none; the effect's other parts still happen. The engine picks from the `random:selection` stream, one draw per picked card, so a reload or replay picks the same cards and the engine log's RNG counters record the draws.

The prototype implements neither card (no precedent at step 2). The read-only Rust reference at `0d6afa7dc2eef6048264ffd634da1c2b97886b12` parses "materialize N <predicate> from your deck" as `StandardEffect::MaterializeRandomFromDeck { count, predicate }` (`rules_engine/src/parser/src/parser/effect/game_effects_parsers.rs` lines 258–264) and gives it no target predicate (`battle_queries/src/card_ability_queries/target_predicates.rs` line 82). It has no runtime behavior and its battle rules say nothing about random selection, so it supports only the untargeted reading.

Nothing in either card says to shuffle, and unlike Discover nobody looks at the deck. The MTG analog, Alchemy's seek, puts a random matching card from the library into hand and leaves the library unshuffled. The deck therefore stays in order. Materialize places the chosen characters in their source zone's order, so both players see which cards left and their relative deck order, but not which places they left. The existing rule for movement within an unshuffled deck applies: a player keeps a card's known place only when the visible removals determine it. The engine resolves the node, collects the cards that actually left each deck (a pick held back by a full back rank stays hidden in place and is no removal), and has each viewer forget exactly the places those removals leave open, through the same interval computation `putInDeck` uses.

A random hand or void reference behaves the same way; a void is public and hand knowledge has no places, so only a deck needs the tracking step. A reference to the opponent's deck takes the opponent's cards, which keep their owner and enter under the effect's controller like any other materialized card.

The DSL form is `randomIn(zone, count, filter, { player, costGreaterThan })`, a `ZoneRandomSpec` (`pick: "random"`) in `ZoneCardSpec`. Both cards compose it directly with `materialize`; D20 requires no scenario module. Synthetic contracts cover both sides' decks, partial and empty matches, a response that empties the deck, reload, replay, rollback, capacity, and the position tracking.
