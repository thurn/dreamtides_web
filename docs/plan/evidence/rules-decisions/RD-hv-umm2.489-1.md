# RD-hv-umm2.489-1: A once-per-turn static void permission holds one allowance per source ability and zone object

- Ladder: 5 for the shared allowance and unlimited → unused once-per-turn → next ordering; 4 for a fresh source zone object and legality checked before costs are paid. Existing permission/Reclaim rules and RD-hv-umm2.81-1 supply the unchanged route semantics.
- rules.md: § Playing Cards and the Stack → Playing from the void.
- Affects: the entity-free `playFromZone("void", filter, { oncePerTurn: true })` static form; downstream printed text on b78d776b-15dd-4d0c-ad12-68b97b8d9fb6 (Starsea Traveler, base/amplified), 96e2c30c-930c-47af-abb0-d4fbab454d56 (Winterbough Guide), 041fafeb-f159-4aba-90c2-3ce4b3038bdc (Gloomantler), and 133e22dd-f81b-406d-b4e3-98c346d7fd4e (Kell Tarn) is authored in their own beads. No production entity is authored here.
- Why: "once per turn" limits the permission itself, shared across every matching card, while each source ability has an independent allowance. A play commits the allowance before responses; preventing it or returning the played card to the void does not refund that allowance. The next turn clears all turn allowances. Unlimited permission use preserves limited permissions; an unused turn allowance renews, so it precedes a one-play permission with no expiry. Permissions of the same class use the existing continuous-effect order. Reclaim is independently chosen and spends no permission allowance. A source's applicable zone remains necessary to offer the permission, but the permission authorizing an announced play is selected before paying its additional costs.
- Ladder evidence: read-only Rust inspection at `rules_engine/src/ability_data/src/static_ability.rs:41` exposes `OncePerTurnPlayFromVoid`, while `battle_queries/src/legal_action_queries/can_play_cards.rs:158–185` and `battle_mutations/src/play_cards/play_card.rs` provide no implemented once-per-turn static path. The [official Magic Comprehensive Rules, effective September 25, 2026](https://media.wizards.com/2026/downloads/MagicCompRules%2020260925.txt), rules 400.7 and 403.4 treat a zone entrant as a fresh object; 601.2e checks casting legality before 601.2f–h determine/pay costs. This adapts the fresh-object rule specifically to static play allowances without changing activated-ability semantics.
- Mechanics: the node's optional `oncePerTurn` flag is restricted to static, filter-based, non-next permissions from public-zone sources or emblems. A once-per-turn source working from a hand or deck raises an explicit unsupported-form error, preserving hidden-source view/determinization contracts. Layer entries retain the actual source ability-list index, including non-static and gained abilities. Permission selection uses `oncePerTurnKey(source, index, enteredZoneAt)` for instance sources and the ordinary key for emblems. The `permission` route records that key after costs succeed on the private step state; a failing step commits no partial write. Existing play events/logs name the UUID-backed instance and reconstruct its selected play behavior through intent replay.
