# RD-hv-umm2.464-1: A ✦ bound reads a card's final spark outside play, and a played card's spark as it was played
- Ladder: 4 (MTG analogs: 613.8 layer dependency, where an effect whose result changes what another applies to is applied first, so a characteristic-defining read sees the dependent layer's result; and "whenever you cast a spell with [quality]" checking the spell as it becomes cast, with last known information afterwards), adapted by rules.md § Spark → Spark outside play, which applies static "have +N✦" abilities only in play
- rules.md: § Spark → Spark outside play; § Ability Types → Order of continuous effects; § Ability Types → Triggered abilities
- Affects: general; the `CardFilter` `sparkAtMost` / `sparkAtLeast` bounds read by static abilities (`grantCardKeyword`, `countCards` zone counts in static values and selector bounds, every `StaticEnv.read` consumer) and by "when you play" / "when the opponent plays" triggers, nth-play counts included. No printed card reaches either path yet.
- Why (static abilities): RD-hv-umm2.452-1 makes a ✦ bound compare a card's current spark wherever it is, gained spark and unexpired spark with a duration included. A static ability ordinarily reads the layers before its own, so a layer-3 keyword grant or a layer-5 spark modifier would read a hand or void card's printed spark and miss the spark it gained (layer 5). That would give one ✦ two meanings. In MTG a dependent effect applies after what it depends on. Here the dependency is one-way: static abilities change base spark and spark only of characters in play, so a card outside play takes its final spark from its copiable values, floating base-spark settings, gained spark, and floating spark changes alone. Reading it expands no static ability, so a static ability whose output changes spark never reads itself, and no loop is possible. A character in play keeps the layer-in-progress reading for `CharacterSelector` bounds, where statics do change spark.
- Why (played records): the turn log records the type, subtype, "has all character types" and copiable cost a card had as it was played (RD-hv-7x4l.34-1), so a later change, or a move to a hidden zone where no side can identify the card, never revisits an earlier play. Spark joins those records on the same footing. Reading the played instance's current spark, as RD-hv-umm2.452-1 did, let an nth-play ✦ trigger fire in the real state but not in a determinization once the card was shuffled into a deck: the view drops the instance link and determinization mints a history-only identity with no spark to read. The recorded spark is non-identifying public information: the card was played face up.
- Mechanics: `src/engine/continuous/layers.ts` `staticReader` gives each static ability the layer-in-progress reader, with the base spark and spark of a character card outside play replaced by `sparkOutsidePlay` (floating layer-4 and layer-5 changes and `status.gainedSpark` over layer 1); `changes(4|5)` throws if a static change names a card outside play. `PlayedCard.spark` (`number | null`) is written by `rules/turn-log.ts` `recordPlayed`; `continuous/characteristics.ts` `playedMatchesFilter` compares it, and a saved record without it reads the existing instance's current spark, else matches no ✦ bound. The view carries it with each play record (recovering a legacy record's spark only from a card the viewer sees), determinization copies it, and `rules/battle/fold.ts` `isTurnLog` validates it.
- Contracts: `src/engine/effects/primitives/contracts/card-filter-spark-layers.contracts.ts`.
