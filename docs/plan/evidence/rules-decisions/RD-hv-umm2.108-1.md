# RD-hv-umm2.108-1: "If it was a survivor, create two instead" reads the dissolved character as it last was in play, through mutually exclusive dissolve triggers
- Ladder: 4 (MTG 603.10a and 608.2h: a leaves-the-battlefield ability, and information about the object in its effect, use the object as it last existed on the battlefield), extending RD-hv-umm2.65-1 from the trigger condition to the clause in its effect
- rules.md: § Ability Types → When a character is dissolved
- Affects: 09e17f29-8ee1-477f-8175-ff37eb1f254a (Seer of the Fallen, amplified); the `notSubtype` field of `CharacterSelector`
- Why: rules.md said what a "when … is dissolved" ability sees as it triggers, not what "it" means once the ability resolves. By then the character is in its owner's void, where it has lost any type an effect gave it in play, so reading the void card would make a Warrior that "gains all character types" a survivor when it triggers the ability and a non-survivor when the ability counts its cards. "It" is the character the ability saw, so the clause reads the same view: its types just before it left play, a character with all character types included, since it is of every type. The engine fixes that view only as the dissolve is armed (`armDissolve`), so the amplified ability is two dissolve triggers on the same text that partition the non-figment characters you control: one matches survivors (`subtype: "Survivor"`) and creates two, the other matches every other character (`notSubtype: "Survivor"`, which a character with all character types never matches) and creates one. Exactly one of them triggers for each dissolve, so the card still triggers once and creates two "instead" of one. The base text has no survivor clause and stays one trigger.
- Mechanics: `src/content/cards/seer-of-the-fallen-09e17f29.ts`; `matchesCharacterWith` in `src/engine/dsl/selectors.ts` rejects a `notSubtype` match when the character is of that type or has all types. A future type remap (C12) that rewrites selector subtypes rewrites `notSubtype` too.
