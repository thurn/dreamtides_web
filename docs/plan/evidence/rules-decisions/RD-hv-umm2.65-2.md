# RD-hv-umm2.65-2: An effect that dissolves several characters dissolves them one at a time, and each dissolve triggers on its own
- Ladder: 1 (D14: triggered abilities queue as each triggering event happens, in the order of those events), then 5 (the simplest reading consistent with every affected text and with D14)
- rules.md: § Ability Types → When a character is dissolved
- Affects: every "when … is dissolved" entity listed in RD-hv-umm2.65-1, with f95cae7b-6502-4dbe-ae26-16853959d9a3, f68774ce-0e94-489f-90a5-68e03a549ff6, and 2e8571c0-4faf-4e7a-a702-26952d2035ee in this bead; every effect that dissolves several characters, such as 7709ea42-d73a-4d6b-b8b3-e3f66f44e9ea ("Dissolve all characters"); and every "leaves play" ability, which already behaves this way
- Why: rules.md did not say whether characters dissolved by one effect are dissolved together. Under D14 an ability triggers on an event as it happens, and Dreamtides has no simultaneous zone change: an effect moves the characters it names one after another, and the Challenge phase resolves its lanes in turn. So each dissolve is its own event, in the order the effect names the characters: chosen targets in the order they were chosen, and "each"/"all" characters in the fixed order, the effect controller's B0→B9 then F0→F8 first. A "when … is dissolved" ability whose card the same effect dissolved earlier is already in the void, where its ability does not work, so it does not see the later dissolves; one dissolved later saw the earlier ones and its own. The MTG analog (step 4), where a "destroy all" effect destroys every creature at once and each dying creature's ability sees all of them, is not adopted, because adapting it needs a notion of simultaneous events that the Dreamtides rules and D14's event-by-event matching do not have.
