# RD-hv-umm2.90-1: A return payment uses the owner's hand and ordinary replacements

- Ladder: 4 for the unqualified return destination and modified-cost payment, with existing rules supplying targeting and source independence.
- rules.md: § Costs, Requirements, and X → Returning a character as a cost; § Targeting; § Activated abilities.
- Affects: de946f5a-1e27-4d40-ae44-9ef8cc041949; 07ceb104-0b27-473a-bc72-e6225479ed83.
- Audit: No D/C/P entry defines the destination of an unqualified return. The current prototype `src/rules/` and `src/battle/` has no generic battlefield-return operation; its Dreamwell void-return examples do not decide this. Read-only Rust `battle_mutations/src/effects/apply_standard_effect.rs:275–292` passes `card_properties::controller` to `card_mutations/move_card.rs:198–215`, which moves within that controller's zone collection. Its `docs/battle_rules/battle_rules.md` has no generic return wording, and unchanged destination text cannot be verified; this is a nonbinding observation, not ladder-3 precedent.
- Source: [Official Magic Comprehensive Rules, effective June 19, 2026](https://media.wizards.com/2026/downloads/MagicCompRules%2020260619.pdf), §400.3 and §118.11, verified for this bead. The owner-hand analog supplies the unqualified destination, consistent with current `rules/zones.ts:returnToHand`. Dreamtides explicitly allows putting an opponent-owned card into "your hand" (§ Zones → Hand), so that explicit holder instruction remains its own operation rather than adopting the analog's global ownership constraint. Modified actions still pay a cost: an ordinary return's created-card or Reclaim replacement satisfies the return payment.
- Outcome: Choose a matching controlled in-play character in either rank, including the source when it is not a chosen target. Targets and earlier costs reserve their cards first. Return costs are planned before commitment and paid once with all other costs afterward; cancellation before commitment pays nothing. The owner receives an ordinary return and its `returnedToHand` event, even when the payer controlled an opponent-owned character. A created character ceases to exist or a reclaimed character is banished through existing zone rules. The activated ability resolves independently using its captured origin, variant and original controller after its source returns or ceases.
- Card text: These two printed clauses already identify the payer's controlled characters. No printed-data edit or additional card-issue file is needed; the destination question is a general rule clarification.
- Ordered composition: Source exhaustion is an in-play payment, and return clears stored counters (§ Exhaust and Awaken; § Counters). A selected return cannot remove the source before a later exhaust or positive-counter payment; earlier source payments may precede self-return. A zero-counter payment is a no-op needing neither counters nor a source, so it succeeds even after a created source ceases; this bounded no-op also covers the same vanished-source zero-payment edge on existing costs. Nested alternatives/optional payments test the same order. This bounded rule concerns the new return path; existing abandon behavior is recorded separately as pre-existing evidence.
