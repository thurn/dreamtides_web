# RD-hv-umm2.692-1: Current-turn occurrence history is an optional-loop resource
- Ladder: 1 (D12 equivalent state with a monotonic gain, and RD-hv-7x4l.36-1's current-turn history rationale); 5 extends that rationale to the admitted discard, departure, dissolve, abandon and captured-provenance records.
- rules.md: § Infinite Loops → Optional Loops and Mandatory Loops; precedent RD-hv-7x4l.36-1.
- Affects: generic engine rule for current-turn history readers and loop offers; this bead changes no catalog UUID or card text.
- Why: `TurnLog` records plays and draws, discard counts, physical departures, dissolutions and abandons, materializations with captured type/figment provenance, and Dawn ability admission counts with observer-qualified lower bounds. These records append or increase until the next turn begins; captured occurrence data stays fixed. During one main window the complete history therefore has the same monotonic role as the earlier play/draw records. `STATE_FIELDS.turnLog` abstracts the whole field from the optional equivalent-position signature, and the gain/loss comparison reads only score, energy, deck size, counters and gained spark. History contributes neither a gain nor a loss, and another admitted resource must establish the shortcut's gain. Every repetition executes actual rules against the current history and checks the recorded actions, prompt answers and automatic-step sequence; an illegal action, changed choice, opponent decision, battle end or diverged sequence stops at its defined boundary while preserving completed steps. Mandatory exact-state hashing includes the complete history, so growing history produces distinct mandatory states. Such a decision-free run reaches the configured resolution cap (default 100,000 automatic steps) unless an existing supported closed-copy proof ends it earlier. The rules text describes these existing classifications and guards; no runtime, loop algorithm, or classification changes are made.
