# RD-hv-umm2.91-2: "X is this character's ✦" reads the character's effective spark as the effect resolves, before a later "Then this character gains +1✦"
- Ladder: 1 (rules.md § Spark: the effective spark, gained spark, spark with a duration, and static and Support spark included, is what rules read; § Spark → Values fixed as an effect resolves and RD-hv-7x4l.7-1: a value in a resolving effect is determined once as it resolves), agreeing with 4 (MTG 608.2h: a resolving ability determines such a value once, as it is applied, from the source's current information; MTG 608.2c: the parts of an ability are applied in written order)
- rules.md: § Spark → This character's ✦
- Affects: c6d8a7cc-3856-4030-96eb-450e406dec33 (Thornwood Delver, "gain X⍟ where X is this character's ✦. Then this character gains +1✦")
- Why: rules.md said which spark rules read and when a resolving effect fixes its values, but no effect read its own source's spark. "This character's ✦" is the source's effective spark like any other read, fixed as the part of the effect that reads it resolves; "Then this character gains +1✦" is a later part, so Thornwood Delver gains points for its spark before the gain. A static ability's values are live and computed inside the layer evaluation that produces spark, so only resolving effects may read a source's spark.
- Open: a source that has left play by the time the effect reads it. MTG 608.2h would use its last known information, as RD-hv-umm2.67-1 and RD-hv-umm2.108-1 do for moved and dissolved cards, but no last-known spark is kept for a queued trigger's source, and keeping one changes the saved trigger queue (`src/rules/battle/fold.ts` `isQueuedTrigger`) and the trigger resolution step (`src/engine/steps/kinds/resolve-trigger.ts`), outside this bead. The engine reads 0 there, and rules.md states no outcome for it.
- Mechanics: the `ValueExpr` member `{ value: "sourceSpark" }` with builder `thisCharacterSpark()` (`src/engine/dsl/values.ts`); `ValueScope.sourceSpark` reads `effectiveSpark` of the source while it is in play (`src/engine/effects/interpreter.ts` `evaluate`). A static ability's scope has none, and evaluating the value there throws.
