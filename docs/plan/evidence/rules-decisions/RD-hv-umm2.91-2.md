# RD-hv-umm2.91-2: "X is this character's ✦" reads the character's effective spark as the effect resolves, before a later "Then this character gains +1✦"
- Ladder: 4 (MTG 608.2h: a resolving ability determines such a value once, as it is applied, from the source's current information; MTG 608.2c: the parts of an ability are applied in written order). rules.md § Spark and § Spark → Values fixed as an effect resolves, with RD-hv-7x4l.7-1, supply the normative effective-spark and resolution-time-value rules.
- rules.md: § Spark → This character's ✦
- Affects: c6d8a7cc-3856-4030-96eb-450e406dec33 (Thornwood Delver, "gain X⍟ where X is this character's ✦. Then this character gains +1✦")
- Why: rules.md said which spark rules read and when a resolving effect fixes its values, but no effect read its own source's spark. "This character's ✦" is the source's effective spark like any other read, fixed as the part of the effect that reads it resolves; "Then this character gains +1✦" is a later part, so Thornwood Delver gains points for its spark before the gain. A static ability's values are live and computed inside the layer evaluation that produces spark, so only resolving effects may read a source's spark.
- Departure: RD-hv-umm2.460-1 applies the retained effective spark immediately before the source leaves play to a queued, stacked, delayed, or resolving ability. An in-play source, including the same card returned to play, supplies its current effective spark.
- Mechanics: the `ValueExpr` member `{ value: "sourceSpark" }` with builder `thisCharacterSpark()` (`src/engine/dsl/values.ts`) reads current effective spark or the ability's `lastKnownSourceSpark` and step-local departure capture (`src/engine/effects/interpreter.ts`). Queued triggers, activated stack items, and delayed trigger records retain departure information across steps, serialization and replay. Static source-spark expressions fail the content gate.
