# RD-hv-umm2.75-1: Abandon choices belong to the abandoning player at resolution
- Ladder: 2 (prototype actual Dreamwell rule), supported by 3 (unchanged Rust Abandon rule and targeting query)
- rules.md: § Keywords and Effects → Abandon
- Affects: the `abandon(chooser, predicate)` primitive; future text encodings for 0269e363-5567-47a4-80cd-8ebc061fe7e1 (Silent Avenger) and 20be0fdd-d691-40a9-b4f8-15689ea7ebaa (The Bastion). This bead authors no catalog entities.
- Why: the primitive catalog specifies a chooser and predicate. The abandoning player chooses a matching character they currently control during resolution. This is a non-targeting choice, so `cannotBeTargeted` does not exclude a character. With no eligible character the choice part does nothing while trailing effects continue. An abandon cost retains its separate play-preparation choice.
- Prototype evidence: at base ca3b8a628c753cd4688c3b81594b63859cd651fb, `src/rules/battle/dreamwell-effects-table.ts:839–874` implements the Bastion's actual printed effect with a resolution-time pick-cards prompt over `alliesInPlay`; `src/rules/battle/effect-step.ts:135–140` enumerates only that player's battlefield occupants, without a targeting restriction. These are rule effects, rather than sandbox edits.
- Reference evidence: read-only `~/dreamtides` at 0d6afa7dc2eef6048264ffd634da1c2b97886b12, `docs/battle_rules/battle_rules.md:275–278` retains the own-character Abandon wording; `rules_engine/src/battle_queries/src/card_ability_queries/target_predicates.rs:64` classifies `EachPlayerAbandonsCharacters` as having no character target.
- Mechanics: `src/engine/rules/costs.ts` owns the guarded `abandonCharacter` rule and delegates to the ordinary zone replacements with no opponent-controlled dissolve. Veil does not replace abandonment. Owner-zone movement, abandoned/dissolved announcements, and created/reclaimed replacements use the shared rules.
