# RD-hv-umm2.168-1: "When you materialize a character" sees its own card's materialization, and "each other character you control" excludes only the card with the ability
- Ladder: 4 (MTG: "Whenever a creature enters" abilities trigger on their own permanent entering, as Soul Warden's does, and "each other creature you control" excludes only the object with the ability)
- rules.md: § Ability Types → When you materialize a character; normative support from § Ability Types → When a character is dissolved and → When you return a character to hand ("a character you control" includes the character with the ability; "another character" does not), → Counting materializations (a card sees its own materialization), and RD-hv-umm2.66-1 ("a character", not "another character", matches its own materialization)
- Affects: 20a6474c-55b8-4b1b-9155-baac62a06f1e
- Why: rules.md said which characters a counted "When you materialize your second …" ability sees, but not whether an uncounted "When you materialize a character" ability sees its own card enter, nor which characters "each other character you control" names. Both readings matter for Crescent Dancer: seeing its own materialization awakens every other character you control as it enters, and excluding only Crescent Dancer awakens each character you later materialize, since the trigger resolves once that character is in play. The text says "a character", not "another character", so the existing rules for "when … is dissolved" and "when you return …" and the MTG analog all include the ability's own card. "Other" contrasts with the card that has the ability, as "another" does throughout rules.md. Crescent Dancer itself stays exhausted when it enters.
- Mechanics: `triggered(whenMaterialize(), p.awaken(all(characterYouControl({ another: true }))))`. The matcher matches `materialized` for the in-play listener's own instance (src/engine/triggers/matcher.ts), and `another` excludes only the source (src/engine/dsl/selectors.ts). Scenario `cards-56` checks both.
