# RD-hv-umm2.52-1: A static ability's keyword reaches cards in a hand, deck, or void only while they are there
- Ladder: 1 (rules.md § Zone Changes: what a card merely has from a static ability does not travel; C4 for a dreamsign's "your deck"), then 4 (MTG 611.3a: a continuous effect from a static ability is not locked in; it applies at each moment to whatever its text names)
- rules.md: § Ability Types → Static abilities; § Zone Changes
- Affects: 6cf545ba-b014-4333-a0da-573e8f97d734 ("Cards in your hand have offering."); 47081bde-f35d-4b5c-ba17-53e5dbf5b419 for the C4 exception only
- Why: rules.md said static abilities apply while their source is in play and listed changes to characters, but no text said whether one could change cards in a hand, deck, or void, which cards "your hand" covers, or what happens as such a card moves. Following the MTG analog, the ability changes each matching card for as long as it is in the named zone and the ability applies, read live like any static ability: a card leaving the zone, or the source leaving play, ends the change, and nothing is recorded on the card, matching the existing rule that spark a character merely has from a static ability does not travel (rules.md now says "spark or keywords a card merely has"). "Your hand" is the hand the controller holds, which is the hand list the engine keeps per holder; "your deck" and "your void" are the controller's own, as the engine keeps them per owner. Type and subtype filters read the card's types after type changes (layer 2), as a static ability's selectors do for characters in play, so a card that still has all character types from an effect with a duration matches every subtype. C4 already decides that a dreamsign's static "your deck" means every journey-deck card wherever it is, so rules.md states that exception beside the rule; implementing it belongs to the bead that authors Green Beetle.
