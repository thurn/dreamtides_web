# RD-hv-7x4l.43-1: "You win the game" on a card in play wins while its condition holds; on a resolving effect it checks the condition as it resolves
- Ladder: 1 (C15: the controller wins in the P5 state-based victory check, and an opponent reaching the score target in the same check draws), then 4 for the event form (MTG 104.2b, an effect may state that a player wins the game; Thassa's Oracle, this card's MTG analog, checks its condition as its effect resolves)
- rules.md: § Objective → Victory check
- Affects: 6e2188f8-580e-4a66-a3e3-267d509de903 (no amplified text)
- Why: C15 places the win in the P5 check "while the card is in play", but the one catalog card it names is an Event, which resolves and moves to the void without entering play, so the literal reading never wins. C15's intent is that its controller wins when the condition holds and that a same-check score win by the opponent draws. A character in play, an avatar, or a dreamsign carrying "you win the game" while a condition holds keeps the C15 reading: any P5 check where the condition is true wins, and a condition true only partway through a step does not. An event or ability whose resolving effect says "you win the game" checks the condition once, as the effect resolves, as the MTG analog does; the win is then applied by the P5 check after that step rather than at once, so the C15 draw against a same-check threshold win still holds. The engine already expresses both forms: `winCondition(condition)` for the ability on a card in play or emblem and `p.winTheGame()` for the resolving effect, which Terminus uses as `event(p.ifThen(noCardsIn("deck"), p.winTheGame()))` (docs/plan/engine-design.md § Victory check). This refines RD-hv-7x4l.1-18, which stated only the in-play form.
