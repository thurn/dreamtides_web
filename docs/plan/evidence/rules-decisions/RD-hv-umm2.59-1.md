# RD-hv-umm2.59-1: Cards an effect chooses from a void are targets, chosen when the card is played and checked again as it resolves
- Ladder: 3 (`~/dreamtides` Rust engine: `target_predicates::get_void_target_predicate` and `effect_prompts` raise a `ChooseVoidCard` prompt for "return … from your void" among the play-time target prompts, and `targeting::void_card_targets` reads the chosen set on resolution), consistent with the rules.md § Targeting example, which already calls the void card of "Abandon a character: Return a character from your void to hand" a target
- rules.md: § Targeting (Cards in a void; Targets are chosen before costs are paid); § Zones → References to cards in a zone
- Affects: 1cfc72e9-b75c-4d55-8bcf-54bb301d7e40, 3811a0a2-66af-4c06-b179-948dfa9b2ee3, 6af8cf81-9e9e-481f-b518-f5dadad99b27, 401bb341-8385-41e9-8f6f-7b48e9ce174d, 7f90d17b-9146-4550-a372-a9d77e814ce6, 975f49d3-213a-43fc-8079-5fe40f126a7b, 4b2f044c-0afe-432a-a121-2ea785bb1182, 3e83cbe2-2b21-4804-9906-4b4735db9869, ed02e610-2e68-4457-95a6-c7c6db60ca40, and every other entity whose text chooses "a/up to N … from your/the opponent's void"
- Why: rules.md did not say whether "a character from your void" is a target, when it is chosen, or what happens when the chosen card leaves the void. Its own Targeting example treats it as a target chosen before costs, and the Rust engine prompts for it with the play-time targets. So a void card is chosen like a character target: at play time for a card or activated ability (a triggered ability as it resolves); a required choice with no candidate makes the play illegal; "up to N" allows none; "cannot be targeted by effects" (C17) keeps a void card out; a card chosen as a target is never also offered to pay a cost of the same play. As the effect resolves, a chosen card still counts only while it is in that void and still matches its filter; when none remains, that part does nothing (noLegalTarget). rules.md § Zone Changes makes targeting follow card identity across zones, so a card that left the void and returned is still the target, unlike the Rust engine's per-zone object ids. The prompt is the existing `chooseTargets` prompt with the `target` role, whose candidates are public void cards.
