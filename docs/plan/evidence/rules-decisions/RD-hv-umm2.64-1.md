# RD-hv-umm2.64-1: Shuffling cards into a deck shuffles it even when no card moves; "shuffle the rest back" shuffles the whole deck
- Ladder: 4 (MTG analog: CR 701.20, Shuffle: an effect that shuffles a set of objects into a library shuffles that library even when the set is empty)
- rules.md: § Keywords and Effects → Shuffle into a deck
- Affects: 5ce69085-aa75-4654-8abe-f9e773931e63, 28f8d95a-be99-4b4c-b9ef-92a4b40fffe7; also the later consumers 50267984-eaa3-415e-a23f-581c54b0ad2d (both variants) and 25d00336-5ad7-433b-8ced-71720a9f074a
- Why: rules.md defined no shuffle effect. No D, C, or P entry covers it. The prototype implements none of these cards (`docs/plan/evidence/legacy-behavior.md`), and the Rust engine has no "shuffle cards into your deck" effect under unchanged text: its deck model draws randomly from a shuffled pool. Two readings needed settling. First, "up to 3 cards" with none chosen, or an empty hand and void: the instruction is still a shuffle, as in MTG, so the deck is shuffled and every card in it becomes unplaceable. Second, Skysign's "shuffle the rest back": the undrawn looked-at cards never left the deck, so shuffling them "back" into it can only mean shuffling the deck. Shuffling only those cards among themselves on top would keep their identities known to the looker and match no other shuffle the rules describe. The engine encodes both cases once, in `shuffleInto`: it always shuffles the controller's deck, and any other deck a card entered, from that deck owner's `shuffle:<side>` stream, then clears both sides' knowledge of every card in it.
