# RD-hv-umm2.88-1: A "shadow figment" is a figment, figment copies included, whose current subtype is Shadow
- Ladder: 1 (rules § Figments: a figment copy "is a figment in every other respect: it counts for effects that refer to figments"; each figment "counts separately as a character and subtype member"), then 5 for the typed reading
- rules.md: § Figments
- Affects: 9d63ba3e-fafb-466e-8418-ce5f8941ba30 (base and amplified), and the later "warrior figments" texts that abandon or count figments by type
- Why: The figment catalog names figment types by subtype (the Shadow figment has the Shadow subtype), and Legionnaire figments are Warriors that "warrior figments" must include, so a typed figment reference reads the subtype rather than the catalog figment identity. It is the existing `figment: true` selector with `subtype`, read from current characteristics like any subtype check: a figment copy of a Shadow character is a shadow figment, a non-figment Shadow character is not, and a figment whose subtype an effect changes matches its new subtype. "If you control no shadow figments" is an intervening condition (rules § Ability Types → Intervening conditions), encoded once as the `controls` condition with `atMost: 0` (`controlsNone`), checked when Night begins and again as the trigger resolves; the opponent's shadow figments do not count.
