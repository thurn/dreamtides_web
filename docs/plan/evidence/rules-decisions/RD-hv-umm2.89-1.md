# RD-hv-umm2.89-1: Draw the first matching deck card, preserving the rest's order and private identities
- Ladder: 5, after checking steps 1–4; existing ordinary draw/Fatigue and knowledge rules supply their established consequences.
- rules.md: § Keywords and Effects → Draw a matching card
- Affects: 017a7b4b-3ccf-4635-9956-28a72b22274e; 8896c178-757e-4775-b117-a4357ebfe30f
- Why: Neither printed instruction specifies a choice, look, reveal, or shuffle. No D/C/P entry defines filtered drawing. The prototype's tutorial effect table (`src/rules/battle/battle-card-effects-table.ts`) has no filtered draw, and the historical rules/battle search for `drawMatching` finds no implementation. P10 excludes sandbox shortcuts. The read-only Rust audit finds `StandardEffect::DrawMatchingCard` declared in `ability_data/src/standard_effect.rs:116`, parsed/serialized and queried for targets, but `battle_mutations/src/effects/apply_standard_effect.rs:41–76` handles ordinary `DrawCards` and falls through `_ => todo!` for this form. There is no implemented Rust precedent to import, regardless of its parser text.
- MTG comparison: [Official Comprehensive Rules, effective June 19, 2026](https://media.wizards.com/2026/downloads/MagicCompRules%2020260619.pdf), §121.1 and §701.23a–b. Ordinary drawing takes the library's top card; searching a hidden zone provides a different operation and allows failing to find specified qualities. These establish no direct filtered-draw analog and do not authorize a search chooser or shuffle for the printed Dreamtides word "Draw". This decision uses the simplest consistent extension: the first eligible card in existing deck order is the drawn card, automatically. The matching opening-hand group in `steps/kinds/begin-battle.ts:43–59` also uses first-match order, but is a separate typed setup rule and is not claimed as prototype precedent.
- Outcome: One matched card moves through ordinary `drawCard`, so draw count, draw triggers, private identity, and existing log/presentation events apply. Skipped cards are neither inspected by a player nor moved, and no RNG/shuffle occurs. A nonempty deck without a match yields no draw; an empty deck causes Fatigue under the explicit ordinary draw rule. A cost criterion uses copiable cost with X as 0, consistent with all other card filters.
- Privacy: An unknown removal's actual hidden index is not public evidence. For each viewer, anonymous source slots remain possible until the first known match, but only when an identifiable source/current origin and its ability's identical literal filters establish a public criterion. Different filters in the ability, opaque synthetic resolution, or a hidden source give only anonymous-removal bounds. Known nonmovers retain their identities/positions exactly when their relation to every possible removal is forced; otherwise their tracking is forgotten. A known selected card has a public exact position. This is local to `drawMatching` and uses the existing `knownTo` schema; no general knowledge API or draw helper is changed.
