# RD-hv-umm2.513-1: Conditional static abilities apply while their public condition holds

- Ladder: 4, adapting Magic Comprehensive Rules 611.3a–b and 604.2: a static effect follows its current text while its source occupies its functional zone. Dreamtides' existing earlier-layer evaluation and once-per-turn source-ability allowance are normative anchors for the adaptation.
- rules.md: § Ability Types → Static abilities and Order of continuous effects; § Playing Cards and the Stack → Playing from the void.
- Affects: the entity-free conditional static form; consuming text on `041fafeb-f159-4aba-90c2-3ce4b3038bdc` (Gloomantler), `3ebaba62-9000-429d-b203-2a5a9724389a` (Radulf), `5190a8b8-25a0-4c60-a4de-2e2c5a73af77` (Cactus), and `28c3ef90-c0dc-4b85-92c8-40758b99e0ce` (Petal-Seer) is authored by their own composition beads. Their additional forms retain their own prerequisites.
- Why: "if" on an always-on ability constrains when the rule applies. The condition reads the current state, using the same characteristics from preceding continuous-effect layers as that ability's selectors and values. An ability cannot read the spark change it itself makes. A conditional void permission selects the existing source/ability/zone-visit allowance; turning its condition off and on changes availability without renewing that allowance. A committed play remains committed if its permission's condition changes afterward.
- Ladder audit: the explicit D/C/P decisions supply no conditional-static evaluation rule. The recorded prototype behavior in `docs/plan/evidence/legacy-behavior.md` implements Support and positional unconditional spark bonuses, with no applicable conditional-static path. Read-only Rust inspection found `StaticAbilityWithOptions.condition` in `rules_engine/src/ability_data/src/static_ability.rs` and its parser/serializer; a source-wide query found no applying conditional-static or `OncePerTurnPlayFromVoid` implementation. This schema does not settle evaluation behavior.
- Primary authority: [official Magic Comprehensive Rules, effective September 25, 2026](https://media.wizards.com/2026/downloads/MagicCompRules%2020260925.txt), 611.3a–b and 604.2, verified through Wizards' rules page. Rule 604.7 also supports keeping resolving-source last-known information outside static evaluation. Dreamtides uses its settled preceding-layer convention rather than importing Magic's dependency ordering.
- Mechanics and public information: `StaticAbility.while` retains source, original ability index, timestamp, and zone-visit provenance. Layer expansion reads it through the characteristics reader preceding that effect's layer. `StaticCondition` accepts the existing public scalar/source predicates, character criteria with non-resolving bounds, unfiltered hand/deck counts, and filtered public void counts. Optional payments and resolving `SourceSparkValue` bounds belong to their existing resolving contexts. The general effect/trigger condition evaluator retains its effective-characteristic semantics. Static conditions add no stored state, event kind, prompt, or display copy; existing action logs, state, UUID-backed source abilities, and allowance records reconstruct each decision.
