## Goal

Turn the load-bearing-but-uncataloged Cumulus patterns into first-class components:
the glass button suite (`IconButton`, `GlassButton`, `GlassDialog`/`GlassBackdrop`),
a shared economy glyph/color table both `Button` and `ResourceChip` render from,
`DreamcallerPortrait` `standing`/`fullBleed` variants that retire the two
quest-start figure forks, a reusable `useScaleToFit` primitive, the rewritten
`Button` doctrine, and the `no-numeric-style-props` ESLint rule that enforces
"variants are enumerated, never open numbers" across the component tier.

This is Phase 2 of the five-phase Cumulus system revisions. It **depends on Phases 0 and 1**:

- **Phase 0** relocated `control-treatment.ts` and `glass-surface.ts` into
  `src/cumulus/internal/`, added a `status?: "stable" | "incubating"` field to the
  `CumulusComponent` registry type plus a `no-ghost-components` integrity check
  (a docs entry needs a real consumer OR `status: "incubating"`), and added a
  duplicate-literal detector with a `BASELINE` allowlist that currently
  grandfathers the thrice-pasted Dreamcaller monogram gradient.
- **Phase 1** folded `glassTrack()` into `glassSurfaceStyle()` and tokenized the
  glass literals behind `--glass-*` tokens. After Phase 1 the ONE glass recipe
  lives at `src/cumulus/internal/glass-surface.ts`; `controlChrome()` and
  `glassIconButtonChrome()` in `src/cumulus/internal/control-treatment.ts` build on
  it. **Write all imports in this plan against `src/cumulus/internal/`.**

If a referenced Phase-0/1 artifact is not present when a task starts, STOP and
surface the gap rather than recreating it.

## Architecture

- **Components** live in `src/cumulus/components/<area>/` (controls, hud, overlay).
  They wear the shared glass material from `src/cumulus/internal/`, route press
  feedback through `Pressable`/`usePress`, and expose strict enumerated props.
- **Primitives** live in `src/cumulus/primitives/` (`useScaleToFit` joins them).
- **Docs**: each component ships a demo module under `src/cumulus/docs/demos/`,
  imported and appended to `CUMULUS_COMPONENTS` in `src/cumulus/docs/registry.ts`.
  Prop metadata is generated by `scripts/generate-cumulus-metadata.mjs` into
  `src/cumulus/metadata/cumulus-metadata.json` (rerun via `npm run cumulus-metadata`,
  covered by `npm run regenerate-assets`).
- **Lint rules** live in `eslint-rules/*.js` with a colocated `*.test.ts`
  (RuleTester + unit tests of exported helpers).

## Tech Stack

React 18 + TypeScript, Vitest (jsdom for component tests), ESLint (flat config)
with `@typescript-eslint/parser`, react-docgen-typescript for prop metadata,
Vite dev server for browser QA, `agent-browser` for automated QA.

## Global Constraints

- **Green at every commit.** `npm run lint`, `npm run typecheck`, and `npm test`
  all pass before every commit. In a fresh worktree run `npm install` first.
- **Conventional commits, pushed immediately.** One commit per task, `git push`
  right after (per AGENTS.md). Never create a branch.
- **No numeric style props.** Components take enumerated string variants, never a
  number-typed visual knob (`size`/`gap`/`scale`/…). Task 8 makes this a lint error.
- **Every new component ships test + demo + registry entry in its own task.** The
  Phase-0 `no-ghost-components` check requires a consumer OR `status: "incubating"`;
  `IconButton`/`GlassButton`/`GlassDialog` are marked `incubating` here and lose
  the flag in Phase 3 when the five bespoke call sites migrate onto them.
- **Browser QA** per `docs/quest_prototype/qa_tooling.md`: isolate every
  `agent-browser` call with a unique `--session`, start the dev server on a
  non-5173 port (`npm run dev -- --port 5174`), assert `location.href` +
  `window.innerWidth` before each screenshot, and tear down only your own server
  (match `dev-with-emulator.mjs --port 5174`, never a broad `pkill -f vite`).
- **Docs never use removed-state phrasing** ("no longer", "we removed", "unlike
  before"). Describe the current system directly.
- **Regenerate after every component change.** New/edited component `.tsx` under
  `src/cumulus/components` or `src/cumulus/primitives` requires `npm run cumulus-metadata`
  (or `npm run regenerate-assets`); commit the regenerated JSON.

### Task 8 — `no-numeric-style-props` ESLint rule (+ test, + config, + allowlist)

Ban number-typed visual knobs on exported component props/view types; allowlist the
production-required box/measure/multiplier values by name.

**Files**
- Create `eslint-rules/no-numeric-style-props.js` — the rule + exported `isKnobName`.

- Modify the ESLint flat config (`grep -l "no-escape-hatch-props" eslint.config.*`) — register + enable the rule with its allowlist under `src/cumulus/components/**`.

**Rule contract**
- **Trigger**: a `TSPropertySignature` member of an exported `interface`/`type` whose
  name ends in `Props` or `View`, in a file under `src/cumulus/components/`, whose
  member name is exactly a knob word or ends with a capitalized knob-word suffix —
  `{size, gap, scale, padding, radius, blur, opacity}` — and whose type is `number`
  (or a union including `number`). Skip files whose basename matches `__*__`. Mirror
  the scaffolding of `no-escape-hatch-props.js` (`toRepoRelativePosix`,
  `SURFACE_PREFIXES`, the interface/type-alias visitors).
- **Allow option**: `{ allow: ["TypeName.member", …] }` exempts a named member so the
  exception is deliberate rather than silently skipped.
- **Message** (`messageId: "numericKnob"`): the prop is a number-typed visual knob /
  arbitrary-customization escape hatch; use an enumerated string variant (e.g.
  `size?: "sm" | "md"`), or, if it is a genuine production measure with no enumerable
  form, add `"TypeName.member"` to the `allow` option with a comment.
- `isKnobName(name)` is exported for unit testing: true for exact knob words and
  camelCase knob suffixes (`badgeScale`, `pipScale`); false for `kind`/`value`/
  `label`/`width`/`height`/`sizePx`/`targetWidthPx`.

**Current offenders (grep-verified, complete):** after Task 1 removed
`ResourceChipProps.size`/`.gap`, the exported `*Props`/`*View` members caught are —
`AtlasNodeView.size`, `AtlasNodeView.badgeScale`, `PressPopoverProps.gap`,
`PressInfoProps.gap`, `DreamcallerPortraitProps.size`. All five are legitimate
box/measure/multiplier values with no enumerable form, so they go in the rule's
`allow` list with per-entry comments. (`PipBadgeProps.scale`, `RulesTextProps`,
`Dreamsign.sizePx`, `Motes`'s `size`, `QuestStatusBar`'s `scale` inline object types
are NOT exported `*Props`/`*View` decls, or the name is not a knob word, so they are
out of scope.)
