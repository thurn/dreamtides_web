Card-name-identity audit — resolved
====================================

The codebase-wide audit of name-keyed card identity (Issues 1-14) is resolved.
All engine, journeys, editor, pool-variant, and script sites that used a card's
display name as an identity key have been migrated to UUID or cardNumber keys,
with display names resolved only at the final render boundary.

Residual: ingestion-boundary name collisions (Issue 14b)
---------------------------------------------------------
scripts/setup-assets.mjs:buildCardMaps and scripts/lib/card-refs.mjs
(loadCardMaps and mapsFromCards) build a `nameToId` map to support legacy
cubecobra source data that carries only display names (no UUIDs or cardNumbers).
When two distinct UUIDs share a display name, `nameToId` retains the first-seen
UUID (first-writer-wins). This is the intended behavior for name-only source
data: the collision cannot be resolved without disambiguated input
(cardNumber-tagged decklists).

All three functions now emit a console.warn listing the colliding name and both
UUIDs when a duplicate is detected, so ingestion runs surface exactly which
cards are merged through this boundary. As of this audit 24 display names in
cards_v2.toml are each shared by two distinct UUIDs; those 24 warnings appear
on each ingestion run.

The collision is upstream of the draft records and merchant corpus. The
adapted draft records in docs/draft_records_adapted/ are UUID-keyed and bypass
this boundary entirely; they are the preferred data source for all algorithms.
