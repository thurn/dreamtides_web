Exploration encounter selection does not draw from the player's journey deck.
`buildExplorationRuntime` in `src/coop/providers/exploration-provider.ts`
filters the authored encounter catalog only by whether each source card exists
in the global card database, then uniformly selects from that catalog. The
canonical design and screen presentation draw an eligible card from the
player's deck and use that card's authored encounter. Align the provider with
the deck-based selection contract and add deterministic tests covering
eligibility, duplicate card instances, and fallback when a drawn encounter
cannot prepare both actions.

Fresh worktrees could not run `scripts/regenerate-assets.sh` because
`scripts/tutorial-data.mjs` read generated `glossary.toml` during module import,
before `setup-assets.mjs` invoked the game-data compiler. This task resolves the
ordering defect by loading glossary IDs only when tutorial triggers are
validated, after generated compatibility data has been materialized.

Fresh worktrees still cannot run `scripts/regenerate-assets.sh` directly because
`scripts/exploration-editor-schema.mjs` reads the gitignored generated
`data/exploration.toml` during module import, before `setup-assets.mjs` can invoke
the game-data compiler. Running `npm run game-data:compile` first works around
the ordering defect.
