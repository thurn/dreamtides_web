The coop reducer version gate does not distinguish uncommitted or generated-content
drift from the checked-in commit. A room created by a dirty-tree development build
can therefore pass the version gate in a clean worktree at the same commit and
then report fold divergences for otherwise valid persisted events.

The tutorial automation gate and the board render payload share one projection.
buildTutorialBattleView maps the opponent-play and dreamwell-reveal checkpoints
to null when their display data is missing (an absent cardInstances entry, a
catalog id mismatch, or a Dreamwell deck lookup miss). Because the shared
controller only completes a presentation after the screen reports that exact id
visible, a display-data miss parks the tutorial permanently instead of degrading
to a plainer render. Surfacing the gating presentationId as its own field,
derived straight from battle.tutorialPresentation and independent of any
display-data lookup, would confine those misses to the rendered payload.

GameCard's reveal spec.primary (src/cumulus/components/card/CardView.tsx,
useRevealSource call inside GameCard) never carries the component's `figment`
or `figmentTitleBar` props even though RevealCard supports both
(src/cumulus/internal/reveal/model.ts and render-reveal-card.tsx already read
card.figment / card.figmentTitleBar). The small on-board GameCardSurface still
renders the figment frame correctly, but the enlarged primary reading copy
shown on hover/press draws a hovered battlefield figment with the ordinary
card frame instead of the figment frame.
