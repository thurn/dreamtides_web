Follow-up: hand-refine the best-fit annotations on five changed tides4 tides
============================================================================

The curated identity annotations (shortName, displayName, displayDescription,
summary, description, color) were restored to data/tides4.jsonc by matching each
baked tide to the pre-removal annotation whose CARD CONTENTS it most resembles
(not by tide id), so the cosmetic facet renumbering re-homes each annotation onto
the deck it actually describes. data/tides5.jsonc inherits these by tide name on
its bake (44 of 64 tides matched). 58 of 64 tides4 tides matched an existing
annotation at >=85% card overlap.

Five tides changed enough that the applied annotation is a best-fit rather than an
exact restoration; a hand pass could sharpen them:

  tide-sig-06 (Corvath)   -> "Discard Void Depth / Echoes in the Abyss" (64%);
      its own pre-removal label, theme preserved.
  tide-fac-14 (Shadowpaw) -> "Warrior Token Flood / Swelling Ranks" (66%).
  tide-fac-28 (Oracle)    -> "Warrior Sacrifice Ramp / The Iron Price" (96%);
      a near-duplicate of tide-fac-10's deck, which carries the same label.
  tide-fac-29 (Harbor Warden) -> "Abandon Disruption / Sacrifice and Sabotage" (77%).
  tide-fac-32 (Torchbearer)   -> "Void Depth Discard / Into Oblivion" (66%).

The bake preserves any hand-edited annotations by tide id (tides4) / tide name
(tides5) on the next re-bake.


Pre-existing: spine-redundancy-experiment.mjs port is not faithful
==================================================================

scripts/spine-redundancy-experiment.mjs carries a hand "re-port" of the
`decklists` pool variant and self-checks it against the real algorithm
(`generatePoolFromData`) before reporting. That self-check aborts with
"PORT IS NOT FAITHFUL" (0/200 pools identical, off by a few cards per pool).

This is pre-existing, not introduced by the card-identity cleanup. On master the
port translated the (already UUID-keyed) archLists/draftLists through a
name -> UUID map, which dropped every member (0 of 82 kept for a sampled slug),
so the port ran with empty archetype/color lists and was already unfaithful. The
cleanup made the port read those UUID-keyed lists directly, which is strictly
closer to the real algorithm, but the hand port still drifts from the live
`decklists` variant in other ways. The experiment is a dormant dev tool (not in
the build pipeline, lint, typecheck, or test suite). Resolving it means re-syncing
the port with the current `decklists` variant or replacing it with a call into
the real generator.
