Pre-existing: /tango ComponentPage layout does not collapse on mobile viewports
================================================================================

src/tango/docs/ComponentPage.tsx lays out the Demo and Controls sections with a
fixed two-column CSS grid (`gridTemplateColumns: "minmax(0, 1fr) minmax(220px,
320px)"`, no responsive media/container query), and PropsTable.tsx renders an
unwrapped `<table>` with no horizontal-scroll container. At narrow viewports
(e.g. the 390x844 iPhone frame used for Tango's mobile-first QA), the Controls
panel does not stack below the Demo panel — it overlaps it — and the props
table's right-hand columns (Default, Description) run off the viewport edge
with no way to scroll to them.

This predates any single component's import: it was latent while
TANGO_COMPONENTS was empty (Phase 1) and first became visible once Pressable
(Phase 2's first real component) gave the page real content to lay out during
mobile QA. It will affect every subsequent component's doc page equally.
Fixing it means adding a narrow-viewport breakpoint to ComponentPage's grid
(stack to one column) and wrapping PropsTable's `<table>` in a horizontally
scrollable container — a change to the shared harness, not to any one
component, so it should land as its own harness task rather than inside a
per-component import.


Pre-existing: spine-redundancy-experiment.mjs port is not faithful
==================================================================

scripts/spine-redundancy-experiment.mjs carries a hand "re-port" of the
`decklists` pool variant and self-checks it against the real algorithm
(`generatePoolFromData`) before reporting. That self-check aborts with
"PORT IS NOT FAITHFUL" (0/200 pools identical, off by a few cards per pool).

This is pre-existing, not introduced by the card-identity cleanup. On master the
port translated the (already UUID-keyed) archLists/draftLists through a
name -> UUID map, which dropped every member (0 of 82 kept for a sampled slug),
so the port ran with empty archetype/color lists and was already unfaithful. The
cleanup made the port read those UUID-keyed lists directly, which is strictly
closer to the real algorithm, but the hand port still drifts from the live
`decklists` variant in other ways. The experiment is a dormant dev tool (not in
the build pipeline, lint, typecheck, or test suite). Resolving it means re-syncing
the port with the current `decklists` variant or replacing it with a call into
the real generator.
