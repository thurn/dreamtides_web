`npm run game-data:parity` defaults `GAME_DATA_PARITY_BASE` to the merge base of
`HEAD` and `master`, then reads each generated `data/*.toml` oracle from that
commit. The current `master` tree does not track those ignored generated TOML
files, so the default command fails at `git show <base>:data/affiliations.toml`
before comparing any dataset. The parity workflow needs a durable historical
baseline, committed semantic fixtures, or an explicit required base that still
contains the compatibility outputs.
