## Dev wrapper can time out while `lsof` stats an Arq SMB mount

`npm run dev -- --port 5184` selected free emulator ports and started asset
setup, then its `lsof` readiness probe warned that a child process was hung
while statting `/Library/Application Support/ArqAgentUNC.noindex/...` and the
wrapper exited with `Timed out waiting for the Realtime Database emulator`.
The documented `npm run dev:vite -- --port 5184` path started successfully, so
Vite-only screen QA remained available. The wrapper should scope its port
inspection so unrelated slow or unavailable mounts cannot block startup.

## Coop battle construction drops opponent reconstruction logs

`createBattleInitProvider` passes a `deferOpponentLog` callback that discards
the deferred emitter from `createBattleInit`. As a result, event-sourced
`BEGIN_BATTLE` construction does not publish `opponent_signature_cards_selected`,
`opponent_deck_constructed`, or the corpus equivalents needed to reconstruct
how the opponent was generated. The provider comment previously claimed the
primary client emitted those records later, but no source consumer retains or
invokes the deferred emitter.

## Reloaded coop battle can render a stale phase after phase intents append

During browser QA on a reloaded `?goto=battle-playable&automation=0&game=...`
room, approving the existing AI end-turn proposal appended its gesture and
returned the fold to the player's Dreamwell phase. Pressing Next Phase then
appended a `SET_BATTLE_FLOW` intent for the player's Day phase to the emulator
room log, but the mounted battle surface continued to render Dawn. Additional
presses appended duplicate Day intents because the client kept computing the
target from its stale rendered phase. Reopening the same room reconstructed the
latest fold state. The room event log and the visible battle board should remain
in sync after every accepted intent so a stale client cannot emit duplicate
phase transitions.
