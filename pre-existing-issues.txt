Task 30 QA — observations

1. Dev-scene reload nuance: `?goto=<scene>` re-derives a fresh scene on every
   full page reload rather than resuming the existing one.

   Cause: the bootstrap effects in src/App.tsx fire on mount while the coop fold
   still holds the seeded genesis state (dreamcaller === null), so their
   `state.dreamcaller !== null` early-return does not yet see the reloaded run.
   They therefore dispatch another LOAD_STATE, and `loadState`
   (src/rules/quest/lifecycle.ts) unconditionally replaces the quest slice, so
   the later-sequenced bootstrap wins and the battle/scene is re-rolled (e.g.
   the opponent changes between reloads).

   Scope: this only affects the developer QA bootstrap flag. Real play does not
   carry `?goto`, so reloading mid-battle (reached via a battle site) re-folds
   the SAME battle cleanly — verified in Task 30 QA scenario 3 on a plain
   `?game=` tab (opponent unchanged across reload).

   Note: before Task 30's append-readiness fix (src/coop/hooks.ts) this
   mount-time bootstrap dispatch silently rejected ("LogClient not ready"), so a
   reload happened to preserve the prior battle by accident. The fix makes the
   intended one-shot bootstrap actually apply; the reload re-derivation is the
   visible trade-off on the dev flag. A future reload-safe guard would gate the
   bootstrap effects on the room's confirmed log being empty (head === 0) rather
   than on the pre-fold `state.dreamcaller`.

Tango Desktop Dreamcaller Select QA — 1280px triptych wraps

- At a 1280×800 viewport, the three fixed 400px Dreamcaller columns plus two
  24px gaps and the outer gutters exceed the available content width, so the
  third column wraps to a second row below the viewport. The desktop layout in
  `src/tango/screens/quest-start-desktop.tsx` should either use a wider desktop
  breakpoint or scale its fixed column geometry before the triptych wraps.

Checks emulator verification — fixed JSON-unsafe optional Dreamcaller metadata

- Once the Checks workflow generated its gitignored runtime catalogs, the
  emulator integration suite reached the real reducer and rejected synthetic
  Dreamcaller state whose optional `portraitFocus` field was materialized with
  the value `undefined`. `toQuestDreamcaller` now omits absent optional focus
  metadata, with a focused regression test covering the JSON-safe shape.

Dream Merchant v2 browser QA — fixed card-source debug update loop

- Dream Merchant card-source debug publication is keyed by the merchant
  encounter signature and keeps the latest coop mutation callback in a ref.
  Applying the published debug state through the room fold therefore leaves the
  encounter mounted without publishing or clearing it again. A ScreenRouter
  regression test re-renders with the folded state and a replacement mutation
  object, then verifies that only the initial publication occurred.
