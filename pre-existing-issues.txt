The Hastened transfiguration has no glossary entry, so card-text tooltips and the glossary popup cannot explain it. Every other transfiguration resolves through `lookupGlossaryTerm`; `src/data/glossary.test.ts` marks Hastened as the known gap.

Dreamscapes and Dream guides are identified at runtime by art-key slugs (`firstlight_meadow`, `tobias_tanglefur`) rather than the UUIDs authored in their catalogs. The compiled runtime data, and therefore `src/content/dreamscapes.ts`, `src/content/guides.ts`, and the guide references in `src/content/sites.ts`, key these entities by slug, contrary to the UUID identity invariant.

QA scenes are not reproducible across loads: with `?goto=<scene>&seed=7`, 22 of 37 scenes (Atlas layouts, site offers, avatar choices, battle hands) render different content on each load, so before/after comparisons of their copy are impossible. Passing an explicit `?game=<id>` for a fresh room leaves the page on "Joining Game" indefinitely instead of creating it. Guide dialogue also picks its line with `Math.random()` on each mount.

`src/battle/state/transition.ts` (`cloneBattleReducerTransition`) has no importers anywhere in the repository; it is dead code left in the sandbox battle state module.

In `src/components/ScreenRouter.test.tsx`, every journey route renders `JourneyCardTutorialController`, which throws "Coop hooks must be used within a CoopProvider" because the router harness mounts without a `CoopProvider`; a nested error boundary catches it, so the tests pass while the controller never mounts and its errors show only as console noise.

The `overlay:cumulus-journey-menu` error boundary's fallback renders beneath the dreamscape layer: when the corner menu crashes, its fallback panel paints under the dreamscape image, so its title is hidden and its buttons (Retry, Recover Game, Export Log) cannot be clicked. The app-shell and screen boundaries are unaffected.

README.md's Architecture "Logging" bullet mentions only the development `logs/journey-log.jsonl` mirror; it does not describe the per-game journey log every build stores in IndexedDB and exports from the game menu and error fallback (D40).

README.md's "Run" section says the app creates a game room in the local emulator and adds `?game=<room-id>`; games are local IndexedDB games, and `/` or `/main` without `?game=` resumes the browser's most recently played game (creating one only when there is none), which the README does not describe.
