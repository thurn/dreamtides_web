Pre-existing: spine-redundancy-experiment.mjs port is not faithful
==================================================================

scripts/spine-redundancy-experiment.mjs carries a hand "re-port" of the
`decklists` pool variant and self-checks it against the real algorithm
(`generatePoolFromData`) before reporting. That self-check aborts with
"PORT IS NOT FAITHFUL" (0/200 pools identical, off by a few cards per pool).

This is pre-existing, not introduced by the card-identity cleanup. On master the
port translated the (already UUID-keyed) archLists/draftLists through a
name -> UUID map, which dropped every member (0 of 82 kept for a sampled slug),
so the port ran with empty archetype/color lists and was already unfaithful. The
cleanup made the port read those UUID-keyed lists directly, which is strictly
closer to the real algorithm, but the hand port still drifts from the live
`decklists` variant in other ways. The experiment is a dormant dev tool (not in
the build pipeline, lint, typecheck, or test suite). Resolving it means re-syncing
the port with the current `decklists` variant or replacing it with a call into
the real generator.


Pre-existing: `bxf bx-refresh` is not a real Boxicons v3 filled class
======================================================================

`src/screens/ShopScreen.tsx:261` renders `<i className="bxf bx-refresh" ... />`
for its reroll affordance. Boxicons v3's filled set (`src/vendor/boxicons/
boxicons-filled.css`) has no bare `.bxf.bx-refresh` rule — only suffixed
variants exist (`bx-refresh-cw`, `bx-refresh-ccw`, `bx-refresh-cw-alt`, etc.),
so this class resolves to no `::before` content and the icon renders blank
(confirmed via `getComputedStyle(el, '::before').content === "none"`).

Found while building the Tango `button` mockup (`src/tango/docs/mockups/
button.tsx`), which had copied the same class for its own reroll row; that copy
was fixed there to `bxf bx-refresh-cw`. `ShopScreen.tsx`'s live reroll button
still uses the blank class and should be updated the same way.


Pre-existing: QuestStart dreamcaller card overflows at wide desktop widths
==========================================================================

The dreamcaller-selection card (`src/screens/QuestStartScreen.tsx`) is a
fixed-height flex column (`h-[472px]`). At wide desktop viewports the 3-column
layout makes each card wide, so the (square) dreamcaller portrait grows tall
enough that the card's own "Starting Essence" footer overflows past the fixed
472px bottom and visually overlaps the tides list rendered below it (measured at
1440x900: essence bottom 753 vs first tide pill 725-751). At narrower/phone-frame
viewports the card content fits and there is no overlap.

This is pre-existing and independent of the Tango component move; it is in fact
reduced by it. Before the move the portrait carried an inline `aspectRatio:
"0.8 / 1"`, which is TALLER than the square panel portrait it now uses, so the
overflow (and overlap) was larger on the prior version. A proper fix reworks the
card so the portrait flex-shrinks into the available space (or the card grows to
fit its content) rather than letting the footer overflow a fixed height.

Pre-existing: Tango readiness gaps found by the mass-production audit
=====================================================================

Found during the Tango readiness review (lint hardening + pilot font fix landed
with this commit); these remain open and block "docs-only" mass production:

1. ~9 exported Tango components have no demo entry and so no generated
   reference: EssenceValue, LeaveSiteButton, HoverPopover, GlowIcon,
   DreamcallerPortrait, CardTermDefinitions, HoverZoomCard,
   GlossaryDefinitionCard, PipBadge, CardStatOrb. Several self-describe as
   "the ONE way" to do something, and the pilot screen imports five of them —
   an agent building from the index alone would improvise duplicates.

2. Popup-rule conflict: SKILL.md mandates InfoCard for every
   reveal-on-interaction popup, but the pilot uses HoverPopover with a
   hand-styled tooltip (SectionHeading) and HoverPopover is undocumented.
   Either bless HoverPopover in the docs with a decision rule vs InfoCard, or
   migrate the pilot's tooltips to InfoCard.

3. tango_design_system.md is a pre-build implementation plan (phases,
   subagent orchestration, prerequisites) that SKILL.md links as "design
   philosophy in depth"; the still-true architecture sections deserve
   extraction into a current-state doc.

4. Screen-composition guidance is missing from the docs: the 1920x1080
   "stage/scaled frame" concept, per-screen Motes/backdrop policy,
   QuestStatusBar wiring (no shared HUD view-model builder exists), z-index
   conventions, target QA viewports, loading/error-state handling, and
   screen-to-screen transition mechanics.

5. No ?goto= QA scenes exist for Draft, Essence, Reward, or dreamscape
   screens, so those migrations cannot be browser-QA'd without playing
   forward.

6. tangoSiteScreenFor's signature carries neither runtimeConfig nor
   onJourneyExplanationChange, which the DreamAugury route needs
   (ScreenRouter.tsx:212-222); that migration requires a registry signature
   change.

7. AGENTS.md declares name-keyed card maps ALWAYS A BUG, but no lint rule
   enforces it; a typed `no-name-keyed-cards` rule (flag .name-keyed
   Map/Set/object keys and name-equality comparisons on card types,
   project-wide) would close the class.
