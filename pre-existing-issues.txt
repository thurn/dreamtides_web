Name-based card identity in the IDF / replay / affiliation engine
=================================================================

Context (shared by all entries below): 24 distinct cards_v2 cards share a
display name with another distinct card (different UUIDs, different rendered
text and rules). AGENTS.md requires identifying cards by stable UUID, never by
name. The draft-record bundle already carries id-aligned fields (`mainboardIds`,
`packIds`, `pickIds`, `signatureCardIds`) so consumers can key on ids.

Already migrated to UUID identity (rendering paths, so the wrong card is NEVER
shown to a player):
  - src/components/PoolViewer.tsx        — record deck, signature cards, and
    replay pick history resolve render targets by id.
  - src/battle/integration/opponent-deck.ts — opponent draft signature seeds
    read `signatureCardIds`.
  - src/screens/QuestStartScreen.tsx     — signature-card React keys / data
    attributes key on the id.

What remains is the SCORING engine, which still keys its corpora on display
name. Impact is bounded and non-visual: a same-name collision blends two cards'
document-frequency / affinity, slightly perturbing steering weights. It never
renders the wrong card. The remaining work is independent of the rendering
migration above and splits into the separate, independently-shippable issues
below. The two scoring subsystems share ONLY the pure `idfCosine` helper, which
is already key-agnostic (src/draft/idf-fit.ts treats keys as opaque strings), so
neither blocks the other.

Hard constraints that apply to every issue below:
  - Lockstep rule (AGENTS.md): an engine and its offline tuning mirror must move
    in the SAME change. Migrating one without the other silently desyncs the
    tuned constants / metric the mirror produces.
  - The pick-data variants (`pickfit`/`pickearly`/`pickpos`/`pickchoice`/
    `pickcohere`/`picksig`) are ALREADY id-keyed (quest-content feeds them
    r.packIds / r.pickIds), so they are NOT part of this work.


Issue 1 — Replay / fit-model family (start here)
------------------------------------------------
Lowest risk, highest confidence, fully self-contained. Has its own corpus, its
own card-number boundary, and its own offline metric for verification. Needs NO
asset-pipeline change: `mainboardIds` / `packIds` / `pickIds` are already
bundled.

Files:
  - src/draft/replay/fit-model.ts        — corpus, idf, prior, co-occurrence,
    neighbour-CF, and the candidate scoring are all in card-NAME space; the
    public API already takes/returns card NUMBERS and translates at the boundary
    via numberToName / nameIndex. Re-key the internals on lowercased UUIDs and
    translate via a number<->id index instead.
  - src/draft/replay/draft-records.ts    — resolveCardNames / selectReplayRecordIndex
    / buildPackSequence key on nameIndex; move to an id index, and score
    selectReplayRecordIndex over packIds + signatureCardIds + id-keyed idf.
  - src/data/quest-content.ts            — buildFitModel(records.map(r => r.mainboard),
    nameIndex) and buildReplayDraftState pass mainboard / signatureCards as
    names. Build a UUID->cardNumber index and feed r.mainboardIds /
    dreamcaller.signatureCardIds instead.
  - scripts/draft-replay-experiment.mjs  — the offline recall@4 harness and the
    source of DEFAULT_FIT_TUNING. Port to the same key space IN LOCKSTEP (it
    already loads via buildDraftRecords, so mainboardIds/packIds/pickIds are
    available).
  - Tests: src/draft/replay/fit-model.test.ts, src/draft/replay/draft-records.test.ts,
    plus any fixtures that hardcode name-keyed corpora.

Verification: run `npm run draft-replay-metric` before and after; recall@4 should
be essentially unchanged (it may shift very slightly as the 24 name collisions
are resolved into distinct cards — that change is a correction, not a
regression). Confirm the metric is reported and stable.


Issue 2 — Pool idf-cosine corpus (idf / idf2 / idf3 / idf4 + affiliations)
--------------------------------------------------------------------------
One atomic unit: idf2Corpus wraps idfCorpus, and idf3 / idf4 / affiliation-weights
all read that same base corpus, so re-keying idfCorpus forces them to move
together — you cannot ship "idf3 on UUIDs" while idf2 stays on names.

Files:
  - src/draft/pool/variant-idf.ts        — idfCorpus builds the IDF corpus from
    poolData.decklists (name arrays); idfCosine is already key-agnostic.
  - src/draft/pool/variant-idf2.ts       — idf2Corpus wraps idfCorpus (near-twin
    diversity weights).
  - src/draft/pool/variant-idf3.ts       — signature probe vs name-keyed idf, AND
    the provenance surface (signatureCardNames / distinctiveCardNames) which is
    shown in the UI: it must key internally on ids but resolve DISPLAY names from
    the id only for the provenance summaries.
  - src/draft/pool/variant-idf4.ts
  - src/affiliations/affiliation-weights.ts — resolves signature UUIDs to names,
    then scores in the name-keyed corpus; score directly on ids instead.
  - Provenance types in src/types/content.ts and the buildDreamcaller*Provenance
    functions in src/data/quest-content.ts that surface idf3 by-name maps.
  - Offline mirrors to move in lockstep: scripts/similar-pool.mjs and
    scripts/idf3-*.mjs (and any other idf-pool tuning script).
  - Tests: variant-idf.coherent.test.ts, variant-idf3.provenance.test.ts,
    variant-idf3.starter-deck.test.ts, affiliation-weights.test.ts, and any
    others that pin name-keyed pool behavior.

Asset-pipeline change required: /decklists-data.json (built by
readAdaptedRecordDecklists in scripts/lib/card-refs.mjs) is name-only today. The
pool corpus needs an id-keyed source — either bundle id arrays alongside the
names in that artifact, or feed poolData id-keyed decklists from another source.
Note the decklists set is NOT identical to the fit-model corpus: decklists keeps
every seat with a non-empty mainboard, while buildDraftRecords requires exactly
30 trimmed picks, so the two corpora differ and cannot simply share one feed.

Verification: the coherent-growth oracle tests (variant-idf.coherent.test.ts pin
idf3 against the idf2 oracle) plus `npm run tides-similarity`. Per AGENTS.md, do
not add tests that pin specific production card names or TOML-derived content.

Signature-id cleanup (fold into whichever of the above ships first)
-------------------------------------------------------------------
`sigseed`'s corpus is already id-keyed (it uses the pick-corpus +
poolData.cardIdByName); only its SIGNATURE INPUT is name-resolved. Same for the
idf3 signature input. quest-content.ts passes dreamcaller.signatureCards (names);
passing the already-loaded dreamcaller.signatureCardIds instead removes the last
name-collision risk on the signature path in a few lines.
